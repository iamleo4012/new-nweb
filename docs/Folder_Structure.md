## 2. `app/` — Next.js App Router

The Next.js application hosts **only** the API surface and the admin panel. There are **no React storefront pages** — the storefront is static HTML (see `public/`).

```
app/
├── layout.tsx               # Bare root layout (<html lang="en"><body/>)
├── api/                     # REST API (Route Handlers)
│   ├── auth/
│   │   ├── login/route.ts
│   │   ├── logout/route.ts
│   │   ├── me/route.ts          # GET (profile) + PATCH (update)
│   │   └── register/route.ts
│   ├── admin/                   # All admin routes gated by requireStaff()
│   │   ├── customers/route.ts
│   │   ├── customers/[id]/route.ts
│   │   ├── hierarchy/[entity]/route.ts
│   │   ├── master/[entity]/route.ts
│   │   ├── orders/route.ts
│   │   ├── products/route.ts
│   │   ├── stats/route.ts
│   │   └── upload/route.ts
│   ├── cart/route.ts
│   ├── catalog/route.ts         # Returns application/javascript (window.NASSIM_PRODUCTS)
│   ├── categories/route.ts
│   ├── orders/route.ts
│   ├── products/route.ts
│   ├── products/[slug]/route.ts
│   └── wishlist/route.ts
└── admin/                       # Admin React SPA (client components)
    ├── layout.tsx               # Injects Tailwind via CDN (not for prod)
    ├── page.tsx                 # default tab = "dashboard"
    ├── AdminApp.tsx             # Shell: header, nav, auth gate, inline tabs
    ├── _components/
    │   ├── CustomersTab.tsx
    │   ├── MasterDataPanel.tsx
    │   ├── MasterDataTab.tsx
    │   └── ProductsTab.tsx
    ├── customers/page.tsx       # thin wrapper, initialTab="customers"
    ├── master-data/page.tsx     # thin wrapper, initialTab="master-data"
    ├── orders/page.tsx          # thin wrapper, initialTab="orders"
    └── products/page.tsx        # thin wrapper, initialTab="products"
```

**Routing notes**
- `next.config.mjs` rewrites `/` → `/index.html`, so the React root layout never renders for the homepage — the static storefront HTML is served instead.
- Admin pages under `app/admin/<section>/page.tsx` are 7-line wrappers that each render `<AdminApp initialTab="…" />`. Navigation is **client-side tab switching**, not URL routing.
- All API routes under `app/api/admin/**` set `export const dynamic = "force-dynamic"`. Public catalog/products/categories routes also force-dynamic (unnecessary; bypasses caching).

## 3. `lib/` — Shared server helpers

```
lib/
├── auth.ts        # Session (DB+JWT), cookie, getSessionUser, requireStaff, publicUser
└── db.ts          # Prisma client singleton (globalThis cache in non-prod)
```

Only two files. There is **no** `lib/validation`, `lib/errors`, `lib/middleware`, or any shared zod schema registry — each API route defines its own zod schemas inline.
